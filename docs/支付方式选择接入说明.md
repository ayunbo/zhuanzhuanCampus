# 支付方式选择接入说明

## 目标

保留现有模拟支付，同时新增简化版虚拟钱包支付。

这里的虚拟钱包是外部 App，不属于校园平台用户体系。
支付时以“当前打开钱包 App 的登录用户”为准。

用户在支付时先选择支付方式：

- 模拟支付
- 虚拟钱包支付

## 统一支付入口

- `POST /user/pay/submit`

请求示例：

```json
{
  "orderId": 10001,
  "payMethod": 2,
  "clientType": "android",
  "returnUrl": "zhuanzhuan://pay/result"
}
```

字段说明：

- `orderId`: 订单 id
- `payMethod`: 1 模拟支付，2 虚拟钱包支付
- `clientType`: `android` / `web` / `h5`
- `returnUrl`: 可选，虚拟钱包支付结束后的返回地址

## 返回说明

### 1. 模拟支付

```json
{
  "orderId": 10001,
  "payMethod": 1,
  "payStatus": 1,
  "action": "direct_success",
  "message": "模拟支付成功"
}
```

前端直接进入支付成功页即可。

### 2. 虚拟钱包支付

```json
{
  "orderId": 10001,
  "payMethod": 2,
  "payStatus": 0,
  "action": "open_wallet",
  "message": "请拉起虚拟钱包完成支付",
  "requestNo": "VW171111111111110001",
  "walletScheme": "virtualwallet://pay?...",
  "redirectUrl": null
}
```

或：

```json
{
  "orderId": 10001,
  "payMethod": 2,
  "payStatus": 0,
  "action": "redirect_page",
  "message": "请跳转到虚拟钱包收银台或拉起钱包应用",
  "requestNo": "VW171111111111110001",
  "walletScheme": "virtualwallet://pay?...",
  "redirectUrl": "zhuanzhuan://pay/result"
}
```

## 钱包页简化要求

钱包页只需要提供：

- 显示订单金额
- 显示钱包余额
- 显示已绑定银行卡及卡内余额
- 显示当前钱包登录用户
- 选择支付渠道：
  - 钱包余额
  - 某张银行卡
- 输入支付密码
- 点击确认支付

支付规则：

- 钱包余额不足：支付失败
- 银行卡余额不足：支付失败
- 密码错误：支付失败
- 成功后回写平台支付结果

## 关系模型

- 下单用户属于校园平台
- 支付用户属于外部钱包 App
- 两者不要求是同一个人
- 平台只接收外部钱包支付结果

## 前端处理建议

### Web/H5

1. 用户点击“虚拟钱包支付”
2. 调用 `/user/pay/submit`
3. 如果返回 `action=redirect_page`
4. 跳转到中转页或收银台页
5. 中转页使用 `walletScheme` 拉起安卓钱包
6. 前端轮询 `/user/pay/status/{orderId}`

### Android 宿主 App

1. 用户点击“虚拟钱包支付”
2. 调用 `/user/pay/submit`
3. 如果返回 `action=open_wallet`
4. 使用 `walletScheme` 直接拉起 `虚拟钱包`
5. 钱包回调服务端后，宿主 App 查询支付状态

## 安卓虚拟钱包需要支持

- Deeplink 打开
- 读取参数：`requestNo`、`orderId`、`orderNo`、`amount`
- 打开一个简单支付页
- 展示当前钱包登录用户
- 用户选择 `钱包余额` 或 `银行卡`
- 用户输入支付密码
- 钱包内部判断余额够不够
- 支付完成后回调：`POST /wallet/pay/callback`
- 回到宿主 App 或 H5 页
