# 通知发布服务接入指南

本文档给后端团队成员使用，目标是让订单、商品审核、卖家认证、举报等业务模块可以用统一方式生成站内通知。

如果你把这份文档交给 AI 生成代码，请要求它严格按本文档调用现有服务，不要新建通知表、不直接写 `NoticeMapper`、不要自己造一套通知接口。

---

## 1. 当前通知发布能力

通知发布统一走后端函数接口：

```java
com.zhuanzhuan.service.notify.NoticePublishService
```

接口文件位置：

```text
zhuanzhuan-common/src/main/java/com/zhuanzhuan/service/notify/NoticePublishService.java
```

实现类位置：

```text
zhuanzhuan-server/src/main/java/com/zhuanzhuan/service/impl/notify/NoticePublishServiceImpl.java
```

通知发布后，后端会自动做这些事：

- 插入一条 `notice` 表记录
- 如果接收用户在线，通过 WebSocket 推送 `notice.message`
- 同步推送通知未读数 `notice.unread`
- 返回一份 `NoticeMessageVO`

调用方只需要关心：谁收通知、是什么业务、业务主键是什么、标题和内容是什么。

---

## 2. 业务模块禁止事项

其他业务模块不要做这些事：

- 不要直接操作 `NoticeMapper`
- 不要自己插入 `notice` 表
- 不要自己拼 `type`、`bizType` 然后绕过 `NoticePublishService`
- 不要调用 `/user/notice/mock/publish` 作为正式业务逻辑
- 不要把前端真实路由写进数据库

正式业务代码必须调用 `NoticePublishService`。

`/user/notice/mock/publish` 只给前端调试面板和联调用，不是正式业务入口。

---

## 3. 如何注入服务

在你的业务 Service 中注入：

```java
import com.zhuanzhuan.service.notify.NoticePublishService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class SomeBusinessService {

    @Autowired
    private NoticePublishService noticePublishService;
}
```

如果你的类已经使用构造器注入，也可以这样：

```java
import com.zhuanzhuan.service.notify.NoticePublishService;
import org.springframework.stereotype.Service;

@Service
public class SomeBusinessService {

    private final NoticePublishService noticePublishService;

    public SomeBusinessService(NoticePublishService noticePublishService) {
        this.noticePublishService = noticePublishService;
    }
}
```

## 4. 五类通知调用方式

### 4.1 卖家认证审核结果通知

适用场景：

- 管理员审核卖家认证通过
- 管理员审核卖家认证驳回

调用方法：

```java
noticePublishService.publishSellerAuthResult(
        receiverUserId,
        sellerAuthId,
        "卖家认证审核结果",
        "你的卖家认证审核已通过，点击查看审核进度。"
);
```

参数含义：

- `receiverUserId`：接收通知的用户 id，通常是提交卖家认证的用户
- `sellerAuthId`：卖家认证记录 id，用于前端跳转到卖家认证审核页面
- `title`：通知标题，不能为空，最长 100 字符
- `content`：通知正文，不能为空，最长 500 字符

前端跳转语义：

- `targetPage = sellerAuth`
- `targetId = sellerAuthId`

---

### 4.2 商品审核结果通知

适用场景：

- 商品审核通过
- 商品审核驳回
- 商品被管理员下架或需要修改

调用方法：

```java
noticePublishService.publishGoodsAuditResult(
        receiverUserId,
        goodsId,
        "商品审核结果",
        "你的商品审核已通过，点击查看商品审核进度。"
);
```

参数含义：

- `receiverUserId`：接收通知的用户 id，通常是商品发布者
- `goodsId`：商品 id，用于前端跳转到商品审核进度页面
- `title`：通知标题，不能为空，最长 100 字符
- `content`：通知正文，不能为空，最长 500 字符

前端跳转语义：

- `targetPage = goodsAudit`
- `targetId = goodsId`

---

### 4.3 订单状态变化通知

适用场景：

- 订单已支付
- 订单已发货
- 订单已完成
- 订单已取消
- 订单超时关闭

调用方法：

```java
noticePublishService.publishOrderStatusChange(
        receiverUserId,
        orderId,
        "订单状态更新",
        "你的订单已发货，点击查看订单进度。"
);
```

参数含义：

- `receiverUserId`：接收通知的用户 id，可以是买家，也可以是卖家，取决于业务需要通知谁
- `orderId`：订单 id，用于前端跳转到订单进度页面
- `title`：通知标题，不能为空，最长 100 字符
- `content`：通知正文，不能为空，最长 500 字符

前端跳转语义：

- `targetPage = order`
- `targetId = orderId`

如果同一个订单事件需要同时通知买家和卖家，请调用两次：

```java
noticePublishService.publishOrderStatusChange(
        buyerId,
        orderId,
        "订单状态更新",
        "你的订单已支付成功，点击查看订单进度。"
);

noticePublishService.publishOrderStatusChange(
        sellerId,
        orderId,
        "订单状态更新",
        "你有一笔订单已支付，请及时处理。"
);
```

---

### 4.4 举报处理结果通知

适用场景：

- 举报已受理
- 举报处理完成
- 举报驳回
- 被举报对象处理结果通知

调用方法：

```java
noticePublishService.publishReportResult(
        receiverUserId,
        reportId,
        "举报处理结果",
        "你的举报已处理完成，点击查看处理结果。"
);
```

参数含义：

- `receiverUserId`：接收通知的用户 id，通常是举报提交者
- `reportId`：举报记录 id，用于前端跳转到举报进度页面
- `title`：通知标题，不能为空，最长 100 字符
- `content`：通知正文，不能为空，最长 500 字符

前端跳转语义：

- `targetPage = report`
- `targetId = reportId`

---

### 4.5 聊天消息通知

聊天模块已经在发送消息时自动接入了聊天通知，一般情况下其他模块不要手动调用。

如果你确实需要手动生成聊天类通知，调用：

```java
noticePublishService.publishChatMessageNotice(
        receiverUserId,
        sessionId,
        "新的聊天消息",
        "你收到一条新的聊天消息，点击查看会话。"
);
```

参数含义：

- `receiverUserId`：接收通知的用户 id
- `sessionId`：聊天会话 id，用于前端跳转到具体聊天页面
- `title`：通知标题，不能为空，最长 100 字符
- `content`：通知正文，不能为空，最长 500 字符

前端跳转语义：

- `targetPage = chat`
- `targetId = sessionId`

注意：

- 聊天模块已经自动发布聊天通知，重复调用会导致重复通知
- 非聊天模块通常不需要调用这个方法

## 5. 什么时候调用

推荐在业务状态真正修改成功后调用通知发布。

例如商品审核：

```java
@Transactional
public void auditGoods(Long goodsId, Integer auditStatus, String rejectReason) {
    // 1. 查询商品
    // 2. 更新商品审核状态
    // 3. 判断接收通知的人
    // 4. 发布通知
}
```

示例：

```java
@Transactional
public void approveGoods(Long goodsId) {
    Goods goods = goodsMapper.getById(goodsId);
    if (goods == null) {
        throw new BaseException("商品不存在");
    }

    goodsMapper.updateAuditStatus(goodsId, 1);

    noticePublishService.publishGoodsAuditResult(
            goods.getSellerId(),
            goodsId,
            "商品审核结果",
            "你的商品已审核通过，点击查看商品审核进度。"
    );
}
```

注意：

- 通知应该跟业务状态变化一致
- 如果业务更新失败，不要发布通知
- 如果一个事件要通知多人，就对每个接收人调用一次

## 6. 参数规则

### 6.1 必填字段

无论调用哪一个语义化方法，下面参数都必须有效：

- `receiverUserId` 不能为空
- 业务 id 不能为空，例如 `goodsId`、`orderId`、`sellerAuthId`、`reportId`、`sessionId`
- `title` 不能为空
- `content` 不能为空

### 6.2 长度限制

- `title` 最长 100 字符
- `content` 最长 500 字符

超过限制会抛出 `BaseException`。

### 6.3 接收人规则

`receiverUserId` 是“谁应该看到这条通知”。

常见映射：

- 卖家认证审核结果：通知提交认证的用户
- 商品审核结果：通知商品发布者
- 订单状态变化：按业务需要通知买家、卖家或双方
- 举报处理结果：通知举报提交者，必要时也可以通知被处理用户
- 聊天消息通知：通知聊天消息接收方

## 7. 高级用法：通用 publish

如果语义化方法不够用，可以调用通用方法：

```java
import com.zhuanzhuan.dto.notify.NoticePublishCommand;
import com.zhuanzhuan.entity.notify.Notice;

noticePublishService.publish(
        NoticePublishCommand.builder()
                .receiverUserId(receiverUserId)
                .type(Notice.TYPE_ORDER)
                .bizType(Notice.BIZ_TYPE_ORDER)
                .bizId(orderId)
                .title("订单状态更新")
                .content("你的订单状态已更新，点击查看订单进度。")
                .build()
);
```

当前常量：

```java
Notice.TYPE_ORDER = 1;
Notice.TYPE_AUDIT = 2;
Notice.TYPE_REPORT = 3;
Notice.TYPE_SYSTEM = 4;
Notice.TYPE_CHAT = 5;

Notice.BIZ_TYPE_GOODS = 1;
Notice.BIZ_TYPE_ORDER = 2;
Notice.BIZ_TYPE_SELLER_AUTH = 3;
Notice.BIZ_TYPE_CHAT = 4;
Notice.BIZ_TYPE_REPORT = 5;
```

建议优先使用语义化方法，只有新增通知类型时再使用通用 `publish(...)`。

## 8. 返回值说明

发布成功后返回：

```java
NoticeMessageVO
```

主要字段：

- `id`：通知 id
- `type`：通知大类
- `title`：标题
- `content`：正文
- `bizType`：业务类型
- `bizId`：业务主键
- `readStatus`：读取状态，0 未读，1 已读
- `createTime`：创建时间
- `actionText`：前端按钮文案
- `targetPage`：前端跳转页面语义
- `targetId`：前端跳转目标 id

一般业务模块不需要使用返回值；返回值主要给调试、日志或扩展使用。

## 9. 前端跳转约定

后端不保存真实前端路由，只保存业务语义。

当前跳转语义：

- 卖家认证：`targetPage = sellerAuth`，`targetId = sellerAuthId`
- 商品审核：`targetPage = goodsAudit`，`targetId = goodsId`
- 订单：`targetPage = order`，`targetId = orderId`
- 举报：`targetPage = report`，`targetId = reportId`
- 聊天：`targetPage = chat`，`targetId = sessionId`

前端根据 `targetPage + targetId` 自己跳转页面。

## 10. 自测方式

### 10.1 后端函数自测

在业务逻辑中调用对应方法后，检查：

- `notice` 表是否新增记录
- `user_id` 是否是目标接收用户
- `biz_type` 和 `biz_id` 是否正确
- `read_status` 是否为 `0`

### 10.2 前端实时推送自测

让目标用户在线，且前端已连接：

```text
ws://localhost:8080/ws/chat?token={JWT}
```

触发业务后，前端应收到：

```json
{
  "event": "notice.message",
  "data": {}
}
```

以及：

```json
{
  "event": "notice.unread",
  "data": {
    "totalUnreadCount": 1
  }
}
```

### 10.3 调试接口自测

如果业务模块还没写完，可以先用调试接口模拟：

```http
POST /user/notice/mock/publish
```

请求体示例：

```json
{
  "receiverUserId": 6,
  "scene": "order_status_change",
  "bizId": 20260330001,
  "title": "订单状态更新",
  "content": "你的订单已发货，点击查看订单进度。"
}
```

注意：这个接口只用于调试，正式业务不要调用它。

## 11. 常见错误

错误：把 `receiverUserId` 传成当前操作管理员 id。

正确：`receiverUserId` 应该是接收通知的普通用户 id。

错误：订单要通知买家和卖家，但只调用了一次。

正确：需要通知几个人，就调用几次。

错误：业务状态还没更新成功就先发通知。

正确：业务更新成功后再发通知，最好放在同一个业务 Service 方法里。

错误：直接插入 `notice` 表。

正确：必须调用 `NoticePublishService`，否则 WebSocket 推送和未读数同步不会统一。

错误：在正式业务里调用 `/user/notice/mock/publish`。

正确：正式业务调用 Java 函数接口，mock 接口只用于开发联调。

## 12. 给 AI 的接入提示词

如果你要让 AI 帮某个业务模块接入通知，可以直接把下面这段发给它：

```text
请在当前 Spring Boot 后端业务代码中接入站内通知发布能力。

必须使用已有服务：
com.zhuanzhuan.service.notify.NoticePublishService

不要直接操作 NoticeMapper，不要直接插入 notice 表，不要调用 /user/notice/mock/publish 作为正式业务逻辑。

根据业务场景选择下面的方法：
1. 卖家认证审核结果：publishSellerAuthResult(receiverUserId, sellerAuthId, title, content)
2. 商品审核结果：publishGoodsAuditResult(receiverUserId, goodsId, title, content)
3. 订单状态变化：publishOrderStatusChange(receiverUserId, orderId, title, content)
4. 举报处理结果：publishReportResult(receiverUserId, reportId, title, content)
5. 聊天消息通知通常已由聊天模块自动处理，不要重复生成；特殊情况才用 publishChatMessageNotice(receiverUserId, sessionId, title, content)

receiverUserId 必须是接收通知的用户 id。
业务 id 必须是对应页面跳转所需的业务主键。
title 不能为空且不超过 100 字符。
content 不能为空且不超过 500 字符。

请在业务状态更新成功后调用通知发布方法。
如果一个事件需要通知多个用户，请分别调用多次。
```
